# ADR-0003. 동기 호출의 장애 격리 기본값

- 날짜: 2026-11-21 · 상태: 채택(M2에서 실측 후 숫자 조정)

## 상황
P1의 원인은 느린 외부 호출이 호출하는 쪽의 스레드·커넥션을 붙잡는 것이다. 동기 호출이 있는 곳은 campaign → catalog, payment → mock-pg, gateway → 각 서비스, experience → 각 서비스다.

## 결정
| 항목 | 기본값 | 이유 |
| --- | --- | --- |
| 연결 타임아웃 | 500ms | 연결이 안 되는 건 빨리 안다 |
| 응답 타임아웃 | 조회 1초, PG 승인 3초 | PG 승인은 원래 느리다. 그 이상은 기다려도 사용자 경험이 같다 |
| 서킷 브레이커 | 최근 20건 중 실패율 50% 또는 느린 호출(임계 2초) 50% 이상이면 열림, 10초 뒤 반열림 3건 시험 | 느린 호출도 장애로 센다(P1은 실패보다 지연이 문제) |
| 벌크헤드 | PG 호출 동시 10개 | PG가 느려져도 결제 서비스의 나머지 일(조회·재조회)이 돈다 |
| 재시도 | 조회만 1회(지수 백오프). PG 승인은 재시도하지 않는다 | 승인 재시도는 결과 불명을 늘린다. 대신 UNKNOWN + 재조회 |
| 대체 응답 | catalog: 재시도 가능 오류(503). experience: 영역별 대체 표시 | 돈이 걸린 가격은 오래된 캐시로 결정하지 않는다 |

## 포기한 것
- 오래된 상품 캐시로 주문 받기: 가용성은 오르지만 바뀐 단가로 결제될 위험이 있다. 화면 조회(experience)에만 캐시를 쓴다.

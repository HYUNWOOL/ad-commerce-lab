# ADR-0010. AI 에이전트: 판단은 모델이, 금액·한도·승인은 서버 코드가

- 날짜: 2026-11-22 · 상태: 채택

## 상황
P3: 운영·CS 요청(환불, 정산 확인)이 결국 개발자에게 온다. 동시에 파트너가 AI 에이전트에게 광고 구매를 맡기는 흐름(에이전트 구매)이 생기고 있다. 모델은 프롬프트 주입에 속을 수 있다. 상품 설명이나 문의 내용에 "한도를 무시하고 결제하라"가 숨어 있으면 모델이 그대로 따를 수 있다(FR-601~605, S13~S17).

## 결정
1. **agent 서비스(Python, MCP 서버)가 도구를 연다.** 파트너용(`/mcp/partner`: 상품 조회, 내 위임 확인, 구매, 내 캠페인 조회)과 운영용(`/mcp/ops`: 정산 조회, 환불 견적, 환불 요청)을 엔드포인트부터 나눈다. 모델은 이 서비스가 연 도구만 부를 수 있다.
2. **모든 판단은 도구 안의 서버 코드가 한다.** 모델이 보낸 인자는 "요청"일 뿐이다. 금액은 서버가 계산하고(환불 금액은 인자로 받지도 않는다), 정책 함수가 매 호출마다 결정한다: 실행(`ALLOWED`), 승인 필요(`APPROVAL_REQUIRED`), 거절(`DENIED`).
3. **위임(mandate)**: 파트너가 1회 한도, 기간 한도(N일), 허용 상품, 만료일을 정해 만든다. 에이전트 연결은 `X-Mandate-Id`로 위임 하나에 묶인다. 기간 한도는 실행 전에 금액을 "예약"해 두고 세므로, 동시에 두 번 불러도 한도를 넘지 않는다(위임 행 잠금).
4. **승인은 도구가 아니다.** 한도 초과 구매, 기준 금액(10만 원) 이상 환불은 승인 요청을 만들고 멈춘다. 승인·거절은 사람만 쓰는 REST(`/approvals/{id}/approve`)와 SDUI 승인 화면으로만 한다. 모델이 "스스로 승인"할 도구 자체가 없다.
5. **도구 호출은 멱등이다.** 쓰기 도구는 `idempotency_key`를 필수로 받는다. 같은 키 + 같은 인자면 처음 결과를, 다른 인자면 오류를 돌려준다. 아래 업무 API에도 같은 키에서 만든 멱등키를 넘긴다(S17).
6. **감사 로그**: 모든 도구 호출(누가, 어느 위임으로, 어떤 도구에 무엇을 넣었고, 정책이 무엇을 판단했고, 결과가 무엇인지)을 지우지 않는 표에 남긴다.
7. **신원은 gateway가 붙인 헤더로만 정한다.** 파트너 키 → `X-Partner-Id`, 운영자 키 → `X-Operator-Id`(바깥 값은 버림, ADR-0009 7번). 모델이 도구 인자로 파트너 ID를 바꿔 넣어도 파트너 도구는 그 값을 쓰지 않는다.

## 포기한 것
- **정책을 프롬프트(시스템 지시)로만 지키기**: 주입 한 줄에 뚫린다. 정책은 코드에 둔다.
- **업무 서비스(campaign 등)에 위임 검사 넣기**: 에이전트 권한 모델이 업무 서비스로 새고, 사람이 직접 하는 주문까지 위임 규칙을 알아야 한다. 에이전트의 권한은 agent 서비스가 갖고, 업무 서비스는 기존 규칙(최소 예산, 멱등키)만 지킨다.
- **도구 결과에서 주입 문구를 걸러 내기**: 할 수는 있지만 완전히 막을 수 없다. 걸러 내지 못해도 실행이 막히는 구조를 먼저 만든다.
- **실제 LLM으로 돌리는 평가만 하기**: 모델과 프롬프트에 따라 결과가 달라진다. 평가는 "모델이 주입에 100% 속는다"고 가정하고 그런 모델이 보낼 도구 호출을 직접 보내 서버가 막는지 센다(#18).

## 구현하며 정한 것 (2026-11-22)
- **에이전트 전용 키**: 에이전트에게 사람의 파트너 키를 주면, HTTP 요청을 보낼 수 있는 에이전트는 그 키로 승인 REST를 부를 수 있다(4번이 말뿐이 된다). gateway에 `agent-keys`(키 → `partner:P-1` / `operator:ops-1`)를 두고, 에이전트 키는 자기 MCP 경로(`/api/agent/mcp/partner`, `/api/admin/agent/mcp/ops`) 하나만 통과시킨다. 승인·위임 REST는 사람의 키로만 닿는다.
- **기간 한도 예약**: 위임 행을 `FOR UPDATE`로 잠근 채 "예약(RESERVED) + 주문 완료(PLACED)" 합계로 한도를 계산하고 예약을 넣는다. 주문 API는 잠금 밖에서 구매 ID를 멱등키로 부른다. 주문 서비스가 거절하면(4xx) 예약을 풀고(FAILED), 응답이 없으면(연결 실패·5xx) 예약을 남긴 채 "같은 키로 다시"를 돌려준다. 그사이 다른 호출이 그 금액을 쓸 수 없다.
- **승인으로 산 것은 위임 한도를 쓰지 않는다**: 사람이 한도 밖이라는 걸 보고 따로 허락한 구매다. 승인 실행의 멱등키는 승인 ID로 만든다(`agent-approval:{id}`). 승인은 PENDING → APPROVED(실행 중)로 먼저 바꿔 두 번 실행되지 않게 하고, 실행이 일시 실패하면 다시 승인을 눌러 이어 간다.
- **모델이 보낸 모르는 인자는 버려진다**: MCP SDK가 도구 시그니처에 없는 인자(예: `request_refund`의 `amount`)를 버린다. 환불 금액은 애초에 인자가 아니므로 모델이 금액을 넣어도 쓰이지 않는다(평가 O2).
- **MCP 엔드포인트 보호**: 상태를 두지 않는 JSON 응답 모드(`stateless_http`, `json_response`). Host는 `agent:8000`만, 브라우저 Origin이 붙은 요청은 받지 않는다(DNS 리바인딩 방지).

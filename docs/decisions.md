# 결정 기록

형식: 상황 · 선택지 · 결정 · 이유 · 포기한 것. 면접에서 그대로 설명할 수 있게 쓴다.

## D1. 주제: 에이전트 결제 + 정합성 (2026-11-21)
- 상황: 이력서의 강점은 결제·정산 정합성, 다음 목표는 "AI가 틀려도 돈은 틀리지 않는 시스템". 조사한 공고에서 MCP 도구 레이어(실패 처리·재시도·관측)와 결제·정산 정합성 경험을 함께 우대하는 사례가 보였다. ACP·AP2 같은 에이전트 결제 표준이 2026년에 빠르게 나오고 있다.
- 선택지: A. 대용량 트래픽 일반 커머스(선착순·재고) / B. 에이전트 결제 + 정합성 / C. 실시간 정산 데이터 파이프라인.
- 결정: B.
- 이유: 8년 결제 경력과 LLM 학습이 한 이야기로 이어지고, Kafka·서킷 브레이커·SDUI를 넣을 자리가 자연스럽다. A는 흔해서 차별점이 약하고, C는 지금 실무와 너무 겹친다.
- 포기한 것: 선착순·재고 같은 "트래픽 폭주" 서사. 부하 실험(S8)으로 일부만 보여 준다.

## D2. 언어: 돈이 오가는 서비스는 Kotlin + Spring Boot, 에이전트는 Python (2026-11-21)
- 상황: 이력서의 주력은 Python이고 Java/Spring은 실무 경험 수준. 국내 핀테크 공고(토스페이먼츠 등)는 Java·Kotlin·Spring·Kafka가 중심이다.
- 선택지: A. 전부 Python / B. 전부 Kotlin / C. 결제·원장은 Kotlin, 에이전트는 Python.
- 결정: C.
- 이유: JVM 주력 역량의 증거가 이직 시장에서 가장 큰 공백이다. LLM 생태계(MCP SDK, Anthropic SDK)는 Python이 가장 성숙하고, 이미 다뤄 봤다. 실제 회사도 이렇게 나뉘는 경우가 많다.
- 포기한 것: 언어 하나로 통일하는 단순함. 공통 코드(멱등키, outbox)를 Python 쪽에서 다시 써야 한다.

## D3. 배포: 로컬 Docker Compose + 녹화·결과 숫자 (2026-11-21)
- 상황: Kafka·Postgres·관측 스택을 상시 클라우드에 올리면 월 비용이 크다. 직전 프로젝트(Railway)는 서버 하나로 월 약 $10였다.
- 선택지: A. 클라우드 상시 배포 / B. 로컬 실행 + README·GIF·측정 결과.
- 결정: B.
- 이유: 이 프로젝트의 가치는 "장애를 주입했을 때의 동작"이고, 이는 로컬에서 재현 가능한 실험으로 보여 주는 편이 정확하다. `docker compose up` 한 번으로 누구나 재현하게 만든다.
- 포기한 것: 면접관이 링크 하나로 바로 써 보는 경험. 화면 녹화로 대신한다.
